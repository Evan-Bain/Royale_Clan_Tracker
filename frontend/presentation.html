⚔️ The Problem
Clan Leaders Have Data, But Not Decisions

Pain Points for Clan Leaders

  • 😤
    Scattered Activity SignalsMember rank, donations, trophies, and war data live in separate views with no clean comparison
  • 👻
    Inactive Members Hide in Plain SightLeaders need a fast way to spot players with no donations and no River Race contribution
  • 📉
    No Memory Between Check-InsWithout saved snapshots, it is hard to tell whether a clan is improving or sliding backward
  • 🎯
    Management by Gut FeelingPromotions, reminders, and removals should be based on visible contribution data

Business Opportunity

A serious clan is a small team. Leaders need a simple product that answers four questions quickly: who contributes, who needs attention, how healthy is the clan, and what changed since the last check-in?

🔥 Challenges We Overcame
Short Lessons From Building the Prototype
01
Merging River Race Data with the Member Roster

The official API returns the roster and current river race separately. We normalize player tags, match participants, and keep the dashboard useful even when some members have no war record.

✓ Solved: mergeMemberData()
02
Firebase Auth Across React and Spring Boot

The frontend signs users in, requests an ID token, sends it as a Bearer header, and the backend verifies it before reading or writing claimed-clan data.

✓ Solved: FirebaseAuthService
03
Designing a Meaningful Participation Score

Raw API values are not enough for a leader. We combined donations, donations received, fame, repair points, boat attacks, and decks used into one explainable score.

✓ Solved: Weighted formula with War Score multipliers
04
Environment Configuration and Deployment Paths

The app needs API base URLs, Clash API credentials, Firebase config, CORS origins, and Firebase Hosting rewrites to line up across local and deployed environments.

✓ Solved: Vite env vars + Spring properties + Firebase hosting rewrites
